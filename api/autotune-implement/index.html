FixOutcome

autotune_implement::FixOutcome

enum FixOutcome

Outcome of a single fix-retry turn (session continuation or fresh respawn). Distinguishes “implementer edited files and we committed” from “implementer made no edits” — the latter is the trigger for a tier-2 fresh respawn or (budget permitting) a final discard.

Variants

  • Committed { commit_sha, session_id } — New commit written on the worktree branch with the given SHA.
  • NoEdits { session_id } — Implementer produced no edits. Session id is returned for callers that want to keep the session alive for another turn, though in practice this is the signal to clear the session and respawn.

Implements: Clone, Debug

build_fix_prompt

autotune_implement::build_fix_prompt

fn build_fix_prompt(fix_history: &[String], latest_test_output: &str) -> String

Build the fix-turn prompt sent into an existing implementer session.

The implementer already has full context from its prior spawn — this prompt only layers on the new information (latest failure plus any prior failures already tried). Kept deliberately terse because the implementer’s context is finite.

build_respawn_prompt

autotune_implement::build_respawn_prompt

fn build_respawn_prompt(hypothesis: &Hypothesis, log_content: &str, denied_paths: &[String], prior_commits: &[String], fix_history: &[String]) -> String

Build the prompt for a fresh respawn (tier-2). The respawned implementer has no session memory, so we re-send the original hypothesis, the list of commits already on the branch, and the full failure history so it can decide whether to continue atop the prior work or rewrite from scratch.

implementation_agent_permissions

autotune_implement::implementation_agent_permissions

fn implementation_agent_permissions(tunable_paths: &[String]) -> Vec<autotune_agent::ToolPermission>

Build sandboxed tool permissions for the implementation agent.

The agent is allowed to read freely but can only edit/write to the specified tunable paths. Running commands, spawning sub-agents, and web access are denied.

run_fix_respawn

autotune_implement::run_fix_respawn

fn run_fix_respawn(agent: &dyn Agent, hypothesis: &Hypothesis, worktree_path: &std::path::Path, tunable_paths: &[String], denied_paths: &[String], log_content: &str, prior_commits: &[String], fix_history: &[String], model: Option<&str>, max_turns: Option<u64>, reasoning_effort: Option<&str>, event_handler: Option<autotune_agent::EventHandler>) -> Result<FixOutcome, ImplementError>

Respawn a fresh implementer on the same worktree with the hypothesis + failure history re-injected. Used when a session-continuation fix turn produced no edits, which we treat as “context exhausted / session stuck”.

run_fix_turn

autotune_implement::run_fix_turn

fn run_fix_turn(agent: &dyn Agent, session: &autotune_agent::AgentSession, worktree_path: &std::path::Path, fix_history: &[String], latest_test_output: &str, event_handler: Option<autotune_agent::EventHandler>) -> Result<FixOutcome, ImplementError>

Continue an existing implementer session with a fix-turn prompt. If the agent edits files the CLI commits them and returns [FixOutcome::Committed]; if it produces no edits, returns [FixOutcome::NoEdits] so the caller can fall through to a fresh respawn.

run_implementation

autotune_implement::run_implementation

fn run_implementation(agent: &dyn Agent, hypothesis: &Hypothesis, worktree_path: &std::path::Path, branch_name: &str, tunable_paths: &[String], denied_paths: &[String], log_content: &str, model: Option<&str>, max_turns: Option<u64>, reasoning_effort: Option<&str>, event_handler: Option<autotune_agent::EventHandler>) -> Result<ImplementResult, ImplementError>

Spawn a sandboxed implementation agent and validate it committed changes.

When event_handler is provided, streaming text and tool-use events are forwarded to it in real time (same mechanism used by the research/init agents). The implementer does not converse with the user — the handler is purely for visibility.
